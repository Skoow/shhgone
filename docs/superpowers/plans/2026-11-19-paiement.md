# Paiement des offres Plus et Pro (Stripe, PayPal, NOWPayments, jetons anonymes) — plan d'implémentation

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal :** vendre Plus et Pro (mensuel, annuel, paiement unique ou renouvellement) par carte (Stripe), PayPal et crypto (NOWPayments), par redirection vers la page hébergée du prestataire, avec un droit délivré à un pass au porteur (`P`) et dépensé en jetons RSA aveugles, sans que le serveur puisse relier un paiement à un partage ou à un salon.

**Architecture :** serveur Go : `internal/paiement` (offres, TVA, base `paiements.db`, prestataires derrière l'interface `Prestataire`, webhooks signés, réserve de jetons `Prendre`) ; routes dans `internal/api/handlers_paiement.go` (seul fichier qui lit `X-Shh-Pass` et les en-têtes des prestataires) ; configuration `internal/config/paiement.go`. Site : `web/src/paiement/` (pass sur l'appareil, client de l'API), page Offres branchée, page `/offres/retour`. Plus tard : jetons Privacy Pass (moteur Rust + circl), relais de sortie, sauvegarde.

**Tech Stack :** Go 1.26 (bibliothèque standard seulement pour les prestataires), `modernc.org/sqlite` v1.62.0 ; Svelte 5, vitest, Playwright ; plus tard `github.com/cloudflare/circl` v1.6.5 et `blind-rsa-signatures` 0.19.0.

**Spec :** `docs/superpowers/specs/2026-11-19-paiement-design.md` (entière) ; spécification principale §36, §38 ; salon v3 §8.

## Global Constraints

- CLAUDE.md : aucune ressource tierce sur le site (redirection seulement) ; aucune IP sur disque ; le serveur ne garde ni nom, ni e-mail, ni pays, ni montant ; aucune crypto maison (HMAC et SHA de la bibliothèque standard, comparaisons en temps constant) ; tests avant tout « fait ».
- Désactivé par défaut : sans `SHH_PAIEMENT=1`, aucune route `/api/paiement/*` (404 uniforme), aucun fichier ni appel sortant.
- Valeurs fixes : spec §1 (prix en centimes 700, 7 000, 2 000, 20 000 ; périodes 30 et 365 jours ; réserves 30 et 100 jetons), §4 (tolérance Stripe ±300 s, 4 vérifications PayPal simultanées, corps de webhook ≤ 256 Kio), §5.7 (rétention 7 jours, fin + 180 jours, fin + 31 jours), §8 (10 commandes par heure par /64, 30 par /48, 1 000 en attente).
- Commits : `--author="Skoow <190851638+Skoow@users.noreply.github.com>"`, lignes d'attribution de la session.
- Vérifications : `cd server && go vet ./... && go test -race ./...` ; site : `npm test && npm run check && npm run build && node scripts/check-dist.mjs` (et `--comptes`) ; e2e Playwright de la page Offres.

## Review Focus

1. Signatures : comparaison en temps constant, refus avant toute lecture de base, tolérance d'horloge Stripe dans les deux sens, corps brut transmis tel quel à PayPal.
2. Un paiement ne crédite qu'une fois (références dans la même transaction que le crédit).
3. Montant et devise vérifiés à chaque confirmation.
4. Rien dans `paiements.db` ne désigne une personne, un partage, un salon ou un compte.
5. Adresses de redirection vérifiées (serveur et site) contre la liste fermée.
